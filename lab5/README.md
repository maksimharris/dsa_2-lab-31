# Лабораторная работа 5

Бонусная программа сети магазинов с асинхронной обработкой операций.

## Запуск

1. Запустите Docker Desktop в режиме Linux-контейнеров.
2. Откройте терминал в папке с `docker-compose.yml` и выполните:

   ```powershell
   docker compose up --build
   ```

3. Откройте [Swagger API](http://localhost:8000/docs), [уведомления](http://localhost:8001/docs) или [аналитику](http://localhost:8002/docs).
4. Войдите в [панель RabbitMQ](http://localhost:15672) как `loyalty` с паролем `loyalty_dev`. На вкладке **Exchanges** найдите `loyalty` и `loyalty.events`, на вкладке **Queues and Streams** — `operations`, `notifier.events` и `analytics.events`.

Данные PostgreSQL и RabbitMQ остаются в именованных томах при остановке через `docker compose down`. Уведомления и статистика хранятся в памяти своих сервисов.

## Как проходит операция

1. `api/schemas.py` описывает три формата операции. В Swagger откройте `POST /operations` и отправьте пример ниже. Ответ `202` означает, что брокер принял сообщение.
2. `worker/domain.py` вычисляет изменение баланса. `worker/main.py` сохраняет операцию и баланс в одной транзакции, публикует событие и затем отправляет ACK брокеру.
3. Проверьте результат в `GET /operations/demo-001`. Пока операция обрабатывается, этот маршрут отвечает `404`. Повтор того же номера операции возвращает сохранённый результат и повторно баланс не меняет.
4. Откройте `GET /accounts/C1042` для просмотра счёта. В сервисе notifier выполните `GET /notifications?customer_id=C1042`, а в analytics — `GET /stores/S12`.

```json
{
  "operation_id": "demo-001",
  "type": "purchase",
  "customer_id": "C1042",
  "store_id": "S12",
  "check_number": "S12-001",
  "amount": "2490.00",
  "occurred_at": "2026-11-10T14:32:05+07:00"
}
```

Для нового покупателя пример начисляет 124 балла. При повторной покупке с тем же номером чека и новым номером операции worker сохранит отказ `duplicate_purchase`. Для возврата передайте номер чека исходной покупки и опустите поля `amount` и `points`. Для оплаты баллами передайте оба поля.

## Проверка

После запуска выполните `python check_lab.py`. Сценарий создаёт покупателя и магазин с уникальными идентификаторами, проверяет три вида операций, шесть причин отказа, баланс, уведомления и аналитику. Для проверки отписки запустите сервисы с переменной `UNSUBSCRIBED=C1042` и отправьте операцию для C1042. Счётчик полученных событий notifier вырастет, а счётчик отправленных уведомлений сохранит своё значение.

Для отчёта снимите вкладки **Exchanges** и **Queues and Streams** после запуска сервисов.
